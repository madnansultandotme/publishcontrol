# PublishControl

PublishControl is a native Python and PySide6 desktop application for preparing and publishing individual npm packages. It provides package inspection, release preparation, archive preview, live logs, publish confirmation, release history, and settings.

## Requirements

- Python 3.10 or newer
- Node.js and npm available on `PATH`
- A graphical desktop environment

On Linux, Qt may also require desktop/XCB libraries such as `libxcb-cursor0`.

## Run

### Windows

```powershell
cd C:\path\to\PublishControl
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.\run.bat
```

### macOS and Linux

```bash
cd /path/to/PublishControl
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
./run.sh
```

You can also start the application directly with `.venv\Scripts\python main.py` on Windows or `.venv/bin/python main.py` on macOS/Linux. Confirm that `npm --version` works in the same terminal.

## Release a package

1. Choose a package folder from Dashboard or Package. PublishControl reads `package.json`, checks npm authentication and the registry version, and reports Git status and missing documentation.
2. Open Publish and choose Patch, Minor, Major, or Custom. Select the registry, tag, and public or restricted access.
3. Acknowledge local version and lockfile changes, as well as script execution. Only prepare projects you trust.
4. Run preflight. The app checks authentication and version availability, updates the version with `npm version --no-git-tag-version --ignore-scripts`, runs `npm install`, and runs available `test`, `build`, and `prepublishOnly` scripts.
5. The app runs `npm pack --dry-run`, then creates the real archive using npm's normal pack lifecycle hooks. Review the file list and compressed size of that archive.
6. Click **Publish package...**, review the package, version, registry, tag, access, and exact command, optionally enter a one-time password, and click **Publish**.
7. Review the success state and History. Public releases include an **Open npm package** button.

Preparation never runs `npm publish`. Publishing uploads the reviewed archive with `--ignore-scripts`, and checks its SHA-256 immediately before upload. Changing release options invalidates the preview and requires new preparation.

## Authentication and local state

Authentication is owned by npm. Sign in from a terminal, for example:

```bash
npm login --registry https://registry.npmjs.org/
```

To use a granular npm token, open **Settings > Authentication & storage**. Remembered tokens are stored in the operating system credential store, not in settings, history, command arguments, or project files. Tokens are scoped to the HTTPS registry entered. The app does not edit `.npmrc`.

Settings and release history are stored under `~/.publishcontrol/`. Set `PUBLISHCONTROL_DATA_DIR` to use another location. The legacy `PUBLISHCONSOLE_DATA_DIR` variable is also accepted. Prepared archives are stored outside the package folder and are removed when invalidated or closed normally.

## Important boundaries

- PublishControl handles individual packages. Select a package inside a monorepo rather than the workspace root. `publishConfig.directory` is unsupported.
- Preparation can change `package.json`, lockfiles, dependencies, and files generated by package scripts. Changes remain after failure or cancellation. The app does not create Git commits, tags, resets, or rollbacks.
- Missing README, license, repository, and clean Git state are warnings. Authentication failures, invalid metadata, `private: true`, existing versions, and command failures block preparation.
- `prepublishOnly` runs before packing. npm pack runs `prepack`, `prepare`, and `postpack`. `publish` and `postpublish` hooks are not run during upload.
- Browser-based npm authentication challenges may need to be completed in a terminal. The GUI provides an optional OTP field but no interactive terminal.
- Package script output appears in live logs. Common npm token patterns are redacted, but package scripts should never print secrets.
- Atomic JSON storage is intended for one running app instance.

## Staged publishing

Choose **Release mode > Stage for approval** before preflight. The app verifies staging support and that the package already exists, prepares the archive, and uploads it with `npm stage publish`. History records the staged release and npm's staging output. A stage is not a live release, so the dashboard's published version is not advanced.

Review a stage with:

```bash
npm stage list <package> --registry https://registry.npmjs.org/
npm stage view <stage-id>
```

A maintainer approves it with `npm stage approve <stage-id>` in an interactive terminal with 2FA. The GUI does not approve stages automatically or track later approvals. Pending stages reserve their version, so a duplicate upload may be rejected by npm.

The first release cannot use npm staging because the package must already exist. Publish the first version directly with suitable authorization, then use staging for later versions.

Reference: [npm stage documentation](https://docs.npmjs.com/cli/v11/commands/npm-stage/).

## Tests

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
```

Tests cover validation, release ordering, archive tampering, failure paths, persistence, cancellation timeout, background GUI jobs, navigation, and preview invalidation. The npm integration test uses a temporary package and does not publish or use your npm account.

## Project layout

```text
main.py              Application entry point
app/core.py          Validation, subprocess runner, npm workflow, and storage
app/ui.py            Qt interface and worker threads
requirements.txt     Python dependencies
run.bat              Windows launcher
run.sh               macOS/Linux launcher
tests/               Service, npm integration, and offscreen GUI tests
```

Additional references: [Qt thread signals](https://doc.qt.io/qtforpython-6/examples/example_widgets_thread_signals.html), [npm version](https://docs.npmjs.com/cli/v11/commands/npm-version/), [npm pack](https://docs.npmjs.com/cli/v11/commands/npm-pack/), and [npm publish](https://docs.npmjs.com/cli/v11/commands/npm-publish/).
